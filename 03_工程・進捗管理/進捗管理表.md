# テスト進捗管理表 v0.1

## 目的
テスト実行が計画どおり進んでいるかを確認し、遅延や阻害要因を早期に把握する。
進捗管理表では全体状況を簡潔に確認し、不具合や課題の詳細はそれぞれの管理先を参照する。

## 各項目の意味
| 項目 | 内容 |
|---|---|
| 日付 | 進捗を確認した時点 |
| 予定実行件数 | その時点までに実行予定だったテスト件数 |
| 実績実行件数 | 実際に実行できたテスト件数 |
| 差分 | 実績実行件数 - 予定実行件数 |
| BLOCKED | 外部要因などにより実行できないテスト件数 |
| 未解決重大不具合 | 未解決の重大な不具合件数 |
| 状況 | 順調／要注意／遅延などの総合的な進捗判断 |
| 主な遅延要因・懸念 | 進捗へ影響している主要な問題や今後の懸念 |

---

## 運用ルール
- 予定実行件数と実績実行件数を比較し、現在の進捗差を確認する。
- 未実施テストに将来のリスクがあっても、まだ遅延していないものは差分へ含めない。
- 将来遅延する可能性があるものは「主な遅延要因・懸念」に記録する。
- BLOCKEDは、現在実行できないテスト件数として記録する。
- 未解決重大不具合は件数のみ記録し、詳細や重大度の評価は不具合管理側を参照する。
- 仕様確認待ちや環境障害などの詳細は課題管理表を参照する。
- 修正待ち・再テスト待ちなど、不具合ごとの詳細状態は原則として進捗管理表には記載しない。
- 修正待ちや再テスト待ちが全体進捗へ大きく影響する場合のみ、主な遅延要因として記載する。

---

## 管理情報の役割分担
### 進捗管理表
全体の進捗状態を確認する。

- 予定と実績
- 現在の遅れ
- BLOCKED
- 重大不具合件数
- 主な阻害要因

### 課題管理
テスト工程を進めるうえで解決が必要な事項を追跡する。

例：
- 仕様回答待ち
- テスト環境障害
- テストデータ不足

### 不具合管理
発生した不具合の詳細と対応状況を管理する。
例：

- 重大度
- 修正状況
- 修正待ち
- 再テスト待ち
- クローズ状況

### リスク管理
将来発生する可能性のある問題を評価する。

例：
- 影響度
- 発生可能性
- 対応方針
