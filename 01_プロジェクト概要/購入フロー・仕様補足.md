# 購入フロー仕様補足

## 1. 文書の目的

テスト計画を作成するために、
主要な購入フローと、その前提となる最小限の仕様を整理する。

## 2. 購入フローの前提

本プロジェクトは、ハンドメイド雑貨ECサイトの
新規開発および初回リリースを想定する。

初めて利用する人が新規会員登録を行い、
そのまま商品を購入できることを主要な利用フローとする。

## 3. 主要な購入フロー

未ログイン状態で商品を閲覧する  
→ 商品をカートへ追加する  
→ 購入手続きへ進む  
→ 新規会員登録を行う  
→ カート内容を維持したまま購入手続きへ戻る  
→ 配送先を入力する  
→ 支払方法を選択する  
→ 注文内容を確認する  
→ 注文データを作成し、注文番号を発行する  
→ 注文状態を「決済待ち」とする  
→ モック決済を実行する  
→ 決済成功後、注文を確定する  
→ 注文完了画面を表示する

## 4. 会員登録の仕様

- 未ログイン利用者が購入手続きへ進む場合、新規会員登録を行う
- 最初にメールアドレスを入力する
- 仮パスワードをメールで受け取る
- 本登録画面で仮パスワードを入力する
- 本登録ではパスワード、氏名を登録する
- 会員登録完了後はログイン状態とする
- 会員登録前にカートへ追加した商品は維持する
- 会員登録後は購入手続きへ戻る

## 5. 配送先の仕様

- 配送先は購入手続き画面で入力する
- 入力した住所は今回の注文情報として保存する

## 6. 支払い・注文確定の仕様

- 支払方法はモックのクレジットカード決済とする(外部決済サービスとの実接続は行わない)
- 注文内容確認後、注文データを作成する
- 注文データ作成時に注文番号を発行する
- 決済前の注文状態は「決済待ち」とする
- モック決済成功後に注文状態を「確定」に変更する
- 注文確定後、注文完了画面を表示する
- 注文完了画面には注文番号を表示する

## 7. 購入完了の条件

以下がすべて成立した時点で購入完了とする。

- 配送先が決定している
- 注文データが作成されている
- 注文番号が発行されている
- モック決済が成功している
- 注文状態が「確定」になっている
- 注文完了画面が表示されている
