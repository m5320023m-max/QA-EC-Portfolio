# ECサイト：画面操作とAPI通信の流れ

## 1. 目的

ECサイトを題材に、画面操作によって発生するHTTP通信と、ブラウザ内だけで完結する処理を整理する。

QAとして、通信・API処理・画面表示のどこに問題があるかを切り分けられるようになることを目的とする。

## 2. システム構成

| 構成 | 役割 |
|---|---|
| フロントエンド（5500番ポート） | HTMLとJavaScriptによる画面表示 |
| APIサーバー（3000番ポート） | 商品情報の取得・金額計算 |
| `localStorage` | カートの商品情報や数量を保持 |

## 3. 商品一覧画面の表示

**操作：** 商品一覧画面 `index.html` を開く。

**処理の流れ**

1. ブラウザがHTMLと`index.js`を読み込む。
2. `index.js`が`GET /api/products`を送信する。
3. APIサーバーが商品マスタから商品情報を取得する。
4. APIがステータスコード200とJSONを返す。
5. `index.js`がJSONを読み取り、商品名・価格・詳細リンクを画面に生成する。

**期待する画面表示**

| 商品 | 価格 |
|---|---:|
| テスト商品A | 1000円 |
| テスト商品B | 2000円 |

**QAの確認観点**

- 正しいAPIが呼び出されるか
- ステータスコードが200か
- レスポンスの商品情報が正しいか
- 取得した情報が画面に正しく表示されるか

## 4. 商品詳細画面の表示

**操作：** 商品Bの「商品詳細を見る」をクリックする。

**処理の流れ**

1. `product.html?id=B`へ遷移する。
2. `script.js`がURLパラメータから商品ID「B」を取得する。
3. `GET /api/products/B`を送信する。
4. APIが商品Bの情報を返す。
5. ブラウザが「テスト商品B」「2000円」を表示する。
6. 取得した商品情報を`localStorage`にも保存する。

**QAの確認観点**

- URLパラメータの商品IDとAPIの取得対象が一致するか
- APIのレスポンスと画面の表示が一致するか
- 別の商品へ切り替えたとき、古い商品情報が残らないか

## 5. 数量変更とカート画面

**操作：** 商品Bの数量を2に変更し、「カートを見る」をクリックする。

この処理では、数量の増減によって新しいAPI通信は発生しない。

**処理の流れ**

1. ボタンクリックをJavaScriptが受け取る。
2. 商品の数量を画面上で変更する。
3. 数量を`localStorage`に保存する。
4. カート画面へ遷移する。
5. カート画面が`localStorage`から商品情報・数量・単価を読み取る。
6. JavaScriptが合計金額を計算して表示する。

**期待する結果**

| 項目 | 値 |
|---|---|
| 商品名 | テスト商品B |
| 数量 | 2 |
| 単価 | 2000円 |
| 合計金額 | 4000円 |

**QAの確認観点**

- 数量変更が正しく反映されるか
- `localStorage`の保存値が正しいか
- カート画面に情報が引き継がれるか
- 数量と単価から計算した合計金額が正しいか

## 6. POST APIによる金額計算

`POST /api/calculate`は、現在の画面操作からは呼び出していない。

APIテストから直接リクエストを送信して検証する。

**リクエスト例**

- Method：POST
- URL：`/api/calculate`
- Content-Type：`application/json`
- Body：`{"productId":"A","quantity":3}`

**期待するレスポンス**

- Status Code：200
- productId：A
- quantity：3
- unitPrice：1000
- total：3000

存在しない商品Cを指定した場合は、404と`Not Found`が返ることを確認する。

## 7. APIテストとE2Eテストの役割

| テスト | 主な確認対象 |
|---|---|
| APIテスト | ステータスコード・レスポンス内容・金額計算・異常系 |
| E2Eテスト | 画面遷移・表示データ・数量変更・カート反映 |

APIテスト5件とE2Eテスト7件をGitHub Actionsで実行し、全12件のPASSを確認した。

ただし、自動テストがPASSしていても、CI環境の日本語フォント不足によって表示が欠ける問題が発生した。

Artifactのスクリーンショットを確認して問題を発見し、フォントのインストールによって解決した。

**学んだこと：** APIの正常応答、DOM上の値、ブラウザでの描画結果はそれぞれ異なる確認対象である。テストがPASSしても、確認対象外の問題が残る可能性がある。
