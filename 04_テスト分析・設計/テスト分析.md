# テスト分析・テスト観点：注文確定機能

## 1. 対象

「注文確定」機能を対象とする。

### 想定フロー

注文確定  
→ モック決済  
→ 注文番号発行  
→ 注文完了

---

# 2. テスト分析

注文確定機能について、正常終了時に必要な処理・データ・状態・表示を整理し、
あわせて異常操作や処理中断が発生した場合に確認が必要な点を分析した。

| ID | 分析対象 | 確認する内容 |
|---|---|---|
| A1 | 正常終了 | 注文内容の確定、決済、注文番号発行、注文状態の確定まで正常に完了すること |
| A2 | 入力・引継ぎデータ | 商品、数量、金額、配送先、支払方法が注文処理へ正しく引き継がれること |
| A3 | 生成データ | 注文成立時に注文番号・注文結果・注文状態が正しく生成または確定されること |
| A4 | 状態 | 正常時・異常時ともに、最終的に成立または未成立の妥当な状態へ確定し、注文状態と決済状態に不整合が残らないこと |
| A5 | 結果通知 | 注文成立時に、ユーザーが注文完了と注文結果を確認できること |
| A6 | 重複操作 | 連打、ページ更新、再操作によって同一の注文・決済が重複して成立しないこと |
| A7 | 処理中断 | ブラウザ終了や通信断が発生しても、中途半端な状態が残らず最終状態へ確定すること |
| A8 | 決済異常 | 決済失敗や決済結果不明の場合に、注文状態を誤って確定しないこと |
| A9 | 外部決済結果 | 決済サービスの結果が確認できた場合、その結果が注文状態へ正しく反映されること |

---

# 3. テスト観点一覧

「テスト観点」は確認したい性質、
「条件・状況」はその性質を確認するための具体的な状況として整理する。

| 大分類  | テスト観点     | 条件・バリエーション   | 確認内容                    |
| ---- | --------- | ------------ | ----------------------- |
| 処理   | 会員登録の完結性  | 正常登録         | 必要な処理が最後まで完了し、会員登録が成立する |
| データ  | 登録情報の正確性  | 正常登録         | 入力した会員情報が意図せず変化せず登録される  |
| 入力   | 必須項目・入力制約 | 未入力・形式不正     | 不正な内容では登録できず、適切にエラーとなる  |
| データ  | 重複会員の防止   | 登録済みメールアドレス等 | 同一条件で不正な重複登録が行われない      |
| 状態   | 会員状態の整合性  | 登録成功・失敗      | 処理結果に応じて正しい会員状態になる      |
| UI   | 登録結果の認識   | 正常登録         | ユーザーが会員登録完了を認識できる       |
| 画面遷移 | 登録後の購入導線  | 会員登録成功       | 登録完了後、購入フローへ正しく進める      |
| 連携   | 会員情報の引き継ぎ | 登録→購入        | 登録したユーザーとして購入処理を継続できる   |


---

# 4. モック決済条件

決済処理の正常・異常状態を確認するため、以下の結果を再現可能とする。

| 結果 | 内容 | 主な確認対象 |
|---|---|---|
| `SUCCESS` | 決済成功 | 正常処理、注文成立 |
| `FAILED` | 決済失敗 | 注文未成立、再注文可否 |
| `TIMEOUT / UNKNOWN` | 決済結果を取得できない | 結果不明時の状態制御、結果確認後の状態反映 |

---

# 5. 仕様確認事項

テスト分析により、以下は仕様の明確化が必要な項目として整理する。

| No. | 確認事項 |
|---:|---|
| 1 | 注文情報を内部で確定・保存するタイミング |
| 2 | 決済処理と注文番号発行の処理順 |
| 3 | 決済結果不明時の状態確認方法 |
| 4 | 決済結果確認の回数・間隔 |
| 5 | ブラウザ終了・通信断発生時のユーザー表示 |
| 6 | 注文結果を確認できない場合の再操作時の扱い |
