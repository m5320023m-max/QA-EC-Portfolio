# 1. テスト分析
主要フローを個々の機能だけでなく、以下の一連のユーザー行動が成立することを分析する。

**未登録ユーザー**  
↓  
**商品を閲覧**  
↓  
**商品をカートへ追加**  
↓  
**カート内容を確認**  
↓  
**購入手続きへ進む**  
↓  
**新規会員登録へ遷移**  
↓  
**新規会員登録**  
↓  
**会員登録成立・ログイン状態になる**  
↓  
**登録前のカート内容を維持したまま購入手続きへ復帰・継続**  
↓  
**配送先を入力**  
↓  
**支払方法としてクレジットカード（モック決済）を選択**  
↓  
**注文内容を確認**  
↓  
**注文確定**  
↓  
**モック決済**  
↓  
**注文成立**  
↓  
**注文番号発行**  
↓  
**注文完了をユーザーが認識**

また、一連のフローを阻害する状態消失、重複操作、
処理中断、決済異常についても確認対象とする。

| ID | 分析対象 | 確認する内容 |
|---|---|---|
| A1 | 主要フローの完結性 | 初回の商品閲覧からカート、新規会員登録を経て注文完了まで、一連の主要フローを正常に完了できること |
| A2 | 商品閲覧 | 未登録ユーザーでも購入対象の商品を閲覧し、購入判断に必要な商品情報を確認できること |
| A3 | カートへの商品追加 | 未登録状態でも購入対象の商品をカートへ追加できること |
| A4 | カート内容 | カートへ追加した商品・数量・金額が正しく表示されること |
| A5 | 会員登録への遷移 | 未ログインユーザーがカートから購入手続きへ進む際、新規会員登録へ進めること |
| A6 | 会員登録 | 有効な会員情報を入力した場合、新規会員として正常に登録されること |
| A7 | 登録後の会員状態 | 会員登録完了後、登録した会員としてログイン状態になること |
| A8 | カート内容の引き継ぎ | 会員登録前のカート内容が登録後も維持され、購入手続きへ復帰・継続できること |
| A9 | 会員と購入内容の紐づき | 登録した会員の購入として、登録前のカート内容が正しく紐づくこと |
| A10 | 配送先 | 配送先を入力でき、入力内容が注文情報へ正しく反映されること |
| A11 | 支払方法 | 支払方法としてクレジットカード（モック決済）を選択できること |
| A12 | 注文内容確認 | 商品、数量、金額、配送先、支払方法を注文内容確認画面で正しく確認できること |
| A13 | 注文処理 | 注文確定、決済、注文番号発行、注文状態の確定まで正常に完了すること |
| A14 | 注文・決済状態 | 正常時・異常時ともに注文状態と決済状態に不整合が残らないこと |
| A15 | 結果通知 | 会員登録結果および注文結果をユーザーが認識できること |
| A16 | 重複操作 | 連打、ページ更新、再操作によって同一注文・決済が重複して成立しないこと |
| A17 | 処理中断 | 通信断やブラウザ終了が発生しても、不整合な注文・決済状態が残らないこと |
| A18 | 決済異常 | 決済失敗や決済結果不明の場合、注文状態を誤って確定しないこと |
| A19 | 外部決済結果 | 決済サービスの結果が確認できた場合、その結果が注文状態へ正しく反映されること |

# 3. モック決済条件
購入フローにおける決済処理の正常・異常状態を確認するため、
モック決済では以下の結果を再現可能とする。

| 結果 | 内容 | 主な確認対象 |
|---|---|---|
| `SUCCESS` | 決済成功 | 注文成立、注文番号発行、注文完了 |
| `FAILED` | 決済失敗 | 注文未成立、注文・決済状態の整合性、再注文可否 |
| `TIMEOUT / UNKNOWN` | 決済結果を取得できない | 結果不明時の状態制御、結果確認後の注文状態反映 |

# 4. 仕様確認事項
テスト分析により、主要フローを確認するために以下の仕様を明確にする必要がある。
なお、テスト計画で既に定義されている以下の内容は仕様確認事項から除外する。
- 未ログイン状態で商品をカートへ追加できる
- カートから購入手続きへ進む際、新規会員登録へ進む
- 会員登録完了後はログイン状態になる
- 会員登録前のカート内容は登録後も維持される
- 会員登録完了後、購入手続きへ戻れる
- 支払方法としてクレジットカード（モック決済）を使用する

| 3 | カートに表示する金額の内訳（商品金額、送料、税など） |
